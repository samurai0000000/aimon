## 0. Corrections & Negative Constraints (Do Not Reintroduce)

1. **Do not sum raw `usage` lines.** Measured: 3051 assistant lines carry `usage`, about 1521 to 1540 unique `(message.id, requestId)` pairs. Keep the line with the greatest `output_tokens` per key. (Assumes streamed duplicates grow monotonically; verified only as a counting rule, so the ground-truth recount checks consistency, not billing truth.)
2. **Every dollar figure is an estimate at official list prices.** Label it "est." everywhere. Never "spend", "charged", "billed". Measured accuracy on 2026-10-08 (Enterprise): estimate $70.72 vs claude.ai usage page $64.19 for Oct 1-8 (+10%); per-day shape differs (Oct 7 high, Oct 2 low), consistent with the page's reporting lag, usage invisible to local files, and possible negotiated rates. The UI says the estimate may run ahead of or behind the billing page. The page's all-products total ($72.76) includes non-Claude-Code usage the transcripts cannot see.
3. **No official non-admin API exists for the account's real spend or limit** (verified against Anthropic docs: Console Admin API needs an Admin key and does not cover Enterprise parent orgs; the Enterprise Analytics API needs a key only the org's primary owner can create; the user is a plain seat holder). Not planned for v1.
4. **No guessed endpoints, no scraping in v1.** The claude.ai usage page's backing request is unknown. A DevTools-derived source is Envelope 4 (optional, unofficial, blocked on user-supplied request).
5. **Never read, log, store, or transmit credential values.** From `<config dir>/.credentials.json` read only `claudeAiOauth.subscriptionType` and `rateLimitTier`. Never touch `accessToken` / `refreshToken`. aimon never writes or refreshes that file (the CLI owns it; concurrent refresh could invalidate tokens). Never copy the file between hosts. Token expiry is irrelevant because no token is used.
6. **Do not hardcode tier names as an exhaustive enum.** Observed: `subscriptionType: "enterprise"`, `rateLimitTier: "default_claude_zero"`. Personal-account strings are not yet observed and must not be guessed. `enterprise` -> Enterprise; any other non-empty value -> `Personal/Other` carrying the raw string; missing file -> `Unknown`. Extend the table only from observed values.
7. **Tier changes semantics, not just labels.** Enterprise: monthly dollar spend limit (user's page: $500, resets Nov 1). Personal subscriptions: rolling usage windows, no dollar limit, so dollars are "API-equivalent value" and are not shown against a dollar budget unless configured.
8. **No prices in source, config defaults, or the repo (user decision).** Prices are retrieved online from `https://platform.claude.com/docs/en/about-claude/pricing.md` (verified 2026-10-08: HTTP 200, `text/markdown`, 48 KB; the HTML URL is 900 KB of app shell and is not parsed). Cached on disk with `fetched_at`. Fetch failure: last good cache, marked stale; no cache at all: tokens counted, cost `unpriced` with an error banner. Never fall back to an embedded table, never show $0 silently. Price values appear only in test fixtures (a saved copy of the page).
9. **The pricing page is documentation, not an API.** Parse by section heading and exact column header and validate every row. *Structural* problems reject the whole fetch and keep the previous cache: missing heading, header or separator, a row with the wrong cell count, fewer than 3 usable models, or more than 25% of table rows anomalous. *Row-level* problems (user decision 2026-10-08, after the first live fetch) quarantine only the affected model, which then stays unpriced (tokens counted, no dollars) while every other model is priced: duplicate model, unparseable or non-positive price, failed 1.25x / 2x / read-not-above-input relations, an unrecognized tier annotation. A drift test with the saved real pages and mutated copies must exist.
14. **Prices can depend on prompt length (user decision 2026-10-08).** Observed on the live page: `Claude Haiku 5.5` has two rows, `(for prompts up to 100,000 tokens)` and `(for prompts over 100,000 tokens)`. The parser reads only that exact annotation form; a model must have exactly one `up to N` and one `over N` row with the same N, else it is quarantined. A message's prompt length is `input + cache_read + cache_write_5m + cache_write_1h` (assumption: the page says "prompt length" and does not say whether cached tokens count; revisit when a tiered model appears in real usage). Over the threshold the upper rate set applies; fast mode for a tiered model is unpriced because the fast table has no row for it.
15. **Prices change over time and history must not be silently rewritten (user decision 2026-10-08).** Every catalog fetched with a new page hash is stored as a version with its fetch time. A message is costed with the latest version whose fetch time is not after the message time; messages older than the first stored version use the first version. Limitation, stated in the UI help text: a price change is applied from when aimon first saw it, not from when Anthropic made it. Observed motivation: Sonnet 5.5 cache read changed from $0.20 to $0.10 between two fetches hours apart, moving the estimate since Oct 1 from about $81 to about $56.
10. **Fixed cards, no contact-based behavior (user decision 2026-10-08).** Three provider cards are always shown in a fixed order: Antigravity, Cursor, Claude. There is no ordering by MCP contact, no hiding until contact, and no daemon-side provider order. Reason, verified 2026-10-08: data availability differs per provider and does not follow MCP contact. Antigravity data exists only while its IDE's `language_server` process runs; Cursor data comes from a token in aimon's config and the cloud API; Claude data comes from transcripts on disk. The collector runs on the poll cycle regardless of any client; do not start or stop collection from session events. A fourth provider is a future question, not part of this plan.
11. **Same-host assumption is explicit, not hidden.** The daemon (user `samurai`, verified with `ps` 2026-10-08) and the transcripts are on the same machine and user; `~/.claude` on `builder` is local ext4 (not NFS). This is the same assumption the Cursor and Antigravity collectors already make. The scan root is configurable and an unreadable root produces a clear per-account error, never a silent empty result. A push source for other machines is a possible later envelope behind the same source interface.
12. **Scope**: only Claude Code transcripts are visible. claude.ai chat and the mobile app are not. Stated in UI help text.
13. **Do not bypass `WebAssets.hxx` sync.** `web/` edits must be mirrored into `include/WebAssets.hxx`.

## 2. Technical Approach & Architecture

### 2.1 Purpose and Non-Negotiable Acceptance Criteria
- Per account: input, output, cache-read, cache-write tokens; estimated USD; message count; by model; by UTC day; last 5h, last 7d, configured window, current billing cycle.
- Totals equal the independent oracle recount (`claude_oracle.py`, same dedup rule, the page parsed by its own code) **exactly**, in token counts and in integer nano-dollars, on the same file set.
- Incremental: a poll must not re-parse unchanged files, and a daemon restart must not re-parse the whole tree.
- Tier detection is automatic and shown as a badge; behavior differs per tier (2.3).

### 2.2 System Architecture Blueprint

```
<configDir>/.credentials.json (2 tier strings)  ─┐
<configDir>/projects/**/*.jsonl (usage)         ─┴► ClaudeCollector (poll cycle, incremental)
                                                      │ implements ClaudeUsageSource  (future sources plug in here)
                                                      ▼
PriceCatalog (online, cached) ──costs──►  ClaudeUsageStore (SQLite, history.db): rows + per-file cursors
                                                      │ aggregates
                          StateStore ─► AggregateStatus.claude ─┬─► McpServer  check_claude_usage
                                                                ├─► WebServer  #quotas Claude card (always shown)
                                                                ├─► HistoryStore samples (claude:<account>)
                                                                └─► MqttPublisher
```

### 2.3 Detailed Specifications, Interfaces & Data Schemas

**Accounts.** `ClaudeConfig.accounts[]`: `{name, configDir, spendLimitUsd (optional), cycleResetDay (optional, 1-28)}`. Empty list => one account `default` at `$CLAUDE_CONFIG_DIR` if set, else `~/.claude`. Transcripts carry no account identity, so attribution is by config directory; a personal account on this host is a second config directory. Two accounts must not share a `configDir` (validated at load: error, not silent merge). The Enterprise account is configured with `spend_limit_usd: 500` and `cycle_reset_day: 1` (user-approved); both off when unset. The cycle runs from the reset day (UTC) of one month to the next; the card shows "est. $X of $Y" only when both are set.

**Tier detection (`ClaudeAccount::detectTier`).** Bounded read (<=64 KiB) of `<configDir>/.credentials.json`; take only the two strings; map per Section 0 item 6. Missing, unreadable, malformed, or group/world-readable file => tier `Unknown` (usage still collected) with a warning in `errorMessage`. Re-detected every poll so a `/login` switch is picked up; a tier change is logged once.

| Aspect | Enterprise | Personal / Other | Unknown |
|---|---|---|---|
| Usage source | transcripts | transcripts | transcripts |
| Dollar label | "est. spend" against `spendLimitUsd` if configured | "est. API-equivalent value" (no dollar limit) | "est. value" |
| Progress bar | est. USD / `spendLimitUsd` over the cycle | none by default; 5h / 7d token totals instead | none |
| Authoritative account source (later) | Envelope 4 (unofficial) | to be determined, not guessed | none |

**`ClaudeUsageSource` interface** (`fetch()` returns normalized rows and per-account tier info). v1 implements `LocalTranscriptSource` only. Rows: `{account, session_id, message_id, request_id, ts, model, input, output, cache_read, cache_w5m, cache_w1h, speed, web_search, sidechain}`. No prompt text, `cwd`, or email is ever extracted.

**`ClaudeCollector` / `LocalTranscriptSource`.** Recursive walk of `<configDir>/projects`; per-file cursor `{path, offset, size, mtime}` persisted in the store so restarts resume. Parse only complete lines (a trailing partial line is deferred, not dropped); size < offset resets that cursor; lines over 4 MiB are skipped and counted. Source lines: `type == "assistant"`, `message.usage`, `message.model`, `message.id`, `requestId`, `timestamp`, `isSidechain`; usage fields `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` with `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` (when the split is absent, treat the whole creation count as 5m and flag it), `speed`, `server_tool_use.web_search_requests`. Sidechain (subagent) usage is real and included. `<synthetic>` model entries are skipped. Runs inside the existing poll cycle, off the request threads.

**`ClaudeUsageStore` (SQLite, existing `history.db`, tables `claude_usage_rows` and `claude_file_cursors`).** Unique key `(account, message_id, request_id)`, upsert keeping the greatest `output`. Rows persist, so transcripts that Claude Code later deletes do not erase history, and restarts do not re-parse. SQL aggregation by UTC day / 5h / 7d / window / cycle / model / account; costing applies the current `PriceCatalog` at query time, so a price refresh re-costs with no re-parse. Retention: rows older than `claude.retention_days` (default 400) pruned.

**`PriceCatalog` (`include/PriceCatalog.hxx`, `src/PriceCatalog.cxx`).** Fetch via the existing `httplib::SSLClient` (OpenSSL already linked for Cursor): host `platform.claude.com`, path `/docs/en/about-claude/pricing.md`, `User-Agent: aimon/<version>`, 20 s timeout, 4 MiB cap, at most 3 same-host redirects; refresh at most once per `claude.pricing_refresh_hours` (24), plus at startup if the cache is missing or old; runs off the poll thread. Parse `## Model pricing` (columns `Model | Base input tokens | 5m cache writes | 1h cache writes | Cache hits and refreshes | Output tokens`; cells like `$12.50 / MTok`, strip `<sup>N</sup>`) and `### Fast mode pricing` (columns `Model | Input | Output`; rows may combine models as `Claude Opus 5 / Claude Opus 4.8`, split on ` / `). Fast-mode cache rates = fast base x the model's standard cache multipliers (docs: modifiers stack). Name to id: lowercase, strip parentheticals, replace spaces and dots with `-` (`Claude Opus 5.5` -> `claude-opus-5-5`); a transcript model id resolves to a catalog id only when it equals it or equals it followed by `-` and exactly eight digits (a date), which resolves `claude-haiku-4-5-20251001` and keeps `claude-opus-5-6` unpriced instead of silently pricing it as `claude-opus-5` (tightened from "longest prefix" during Envelope 1). Row validation: five values present and > 0; 5m write = 1.25 x input and 1h write = 2 x input within 1%; cache read <= input; fewer than 3 models or any missing column rejects the whole fetch. Cache file `claude_prices.json` (`0600`, atomic temp+rename) with `{source_url, fetched_at, sha256_of_page, models{...}}`. Fast-mode usage on a model with no fast rates is counted as unpriced-fast, not charged at standard rates. US-only inference (1.1x) is not detectable from transcripts and is ignored (documented inaccuracy). Web search requests are counted but not priced in v1 (the rate is prose, not a table); the status flags that web search cost is excluded. Status exposes `pricing: {source_url, fetched_at, stale, models_loaded, error}`; the UI shows "prices as of <date>" and a stale badge after 3x the refresh interval.

**Cost arithmetic.** Costs are integer nano-dollars, never floating point. A price of `$P / MTok` is `P x 1000` nano-dollars per token, so every price with at most 3 decimals converts exactly; a price with more decimals rejects the fetch. Per row: `tokens x nano_per_token` summed across components (input, 5m write, 1h write, cache read, output), where fast-mode and cache multipliers are applied to the integer rate with round-half-up once per rate, identically in the oracle. Aggregates sum integers; conversion to dollars happens only at display (`nano / 1e9`). Overflow bound: `int64` holds about 9.2e18 nano-dollars ($9.2 billion), asserted in tests for the maximum plausible batch.

**Models.hxx**: `ClaudeTier`, `ClaudeModelUsage`, `ClaudeDailyPoint`, `ClaudeAccountStatus {name, tier, rawSubscriptionType, rawRateLimitTier, hasData, windowDays, totals, last5h, last7d, todayEstUsd, estUsdWindow, estUsdCycle, spendLimitUsd, estPctOfLimit, cycleResetIso, models[], daily[], skippedLines, unpricedModels[], pricing, errorMessage}`, `ClaudeStatus {accounts[]}`; `AggregateStatus.claude`; snake_case `toJson()` like existing structs.

**ConfigManager**: `ClaudeConfig {enabled=true, windowDays=30, retentionDays=400, accounts[], pricingUrl, pricingRefreshHours=24}` through all three existing paths (JSON, libconfig read, libconfig write), as Cursor is. No price values in config. Env override: `CLAUDE_CONFIG_DIR` for the default account only.

**Consumers**: `check_claude_usage` (read-only, in the `core` profile, same gate list as `check_cursor_usage`) and a section in `get_combined_ai_status`; history samples `claude:<account>/est_cost_usd` and `/total_tokens`; MQTT discovery and state topics per account; web `#quotas` Claude card per account (own card, per the grid plan's one-card-per-provider rule) with tier badge; `.claude/skills/aimon/SKILL.md` and `references/tools.schema.json`; `doc/Design.md`, README, `TODO.md` (remove the superseded "Claude Desktop local token cache" backlog line). The Android app, ncurses console, and Home Assistant cards read the same status JSON and are checked for tolerance of the new `claude` key (Android `QuotaParserTest`) in Envelope 3.

### 2.4 Threat Model, Safety & Failure Invariants
- Missing or unreadable config or projects dir: that account `hasData=false` with `errorMessage`; other accounts and the daemon are unaffected. Never a silent empty.
- Malformed or truncated JSON line: skipped and counted, never fatal.
- Transcripts contain prompts and file contents: only the row fields are extracted; nothing else is stored or served. Tests assert this on serialized output.
- Credentials: bounded read, two string fields only, never logged, never written; warn if group/world-readable.
- Memory and disk: dedup and aggregation happen in SQLite, not an unbounded in-memory map; row retention bounds disk; per-poll work is bounded by new bytes.
- Concurrency: store access serialized per the existing `HistoryStore` mutex pattern; reads return copies; the price fetch never blocks a poll.
- Network: the only outbound call is the pricing fetch; a dead network leaves stale prices, never a hung poll.
- `/api/*` stays 403 per the MCP-primacy rule; the card uses the same channel the Cursor card uses.

## 3. Staged Implementation Plan & Acceptance Criteria

### 3.0 Gate protocol (non-negotiable)

- A gate is a JSON spec sealed with `python3 <path-to-intelligence>/scripts/plan_gate.py seal --spec <spec> --gate-dir plan/plan_claude_usage_collector.artifacts/gates/<gate-id>`, **before** the envelope's implementation starts. A gate spec is `{gate_id, runs[]}`; each run has `id`, `command` (exact argv list), `expect_exit`, `require_output`, `forbidden_output[]`, optional `identity{}` and optional `records{min_count, required_fields, match_pairs, equals, min_distinct, unique_field, consecutive}`.
- Each run is executed with `plan_gate.py record --gate-dir ... --run <id> [--records f] [--identity f] -- <argv>`; the argv must equal the sealed argv. `plan_gate.py verify --gate-dir ...` must exit 0 on the unaltered seal before the next envelope may start. A retry uses a new attempt id with identical criteria; changing criteria needs the user's approval.
- Every gate contains at least one **negative control**: a run that must fail (`expect_exit` non-zero) when the check is fed a deliberately wrong input, proving the check can fail. A gate without one is invalid.
- Sealing happens at the start of the envelope, after a read-only look at the facts the argv depends on (for example `aimon --help` for daemon flags). Argv containing user paths use paths under `./build/` (no shell expansion in argv).
- **Independent oracle**: `plan/plan_claude_usage_collector.artifacts/oracle/claude_oracle.py` (Python standard library only, run with `-I`, test tooling only and never shipped) re-parses the pricing page and the transcripts with its own code and the same integer arithmetic (2.3). It is written in Envelope 1 before the C++ it checks and is not changed afterward without a new attempt id.
- **Acceptance**: the agent cannot accept. After `verify` passes, the user runs `plan_gate.py accept` with their token. Plan state stays `Executing` until the user accepts and commits.
- Standard `forbidden_output` for C++ test runs: `Errors (`, `Assertion failed`, `Segmentation fault`; for sanitizer runs additionally `AddressSanitizer`, `LeakSanitizer`, `runtime error:`.
